# 黄金问答集（golden_set）说明

评估只需要你准备这一份数据。每行一条，支持 `.jsonl`（每行一个 JSON）或 `.json`（JSON 数组）。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `user_input` | ✅ | 用户问题（会真实送入你的 RAG 管线检索+生成） |
| `reference` | ⚠️ 推荐 | 标准 / 真实答案。用于 `context_recall` / `context_precision`；缺省则这两项指标自动跳过 |
| `response` | ❌ | 你手动准备的「系统答案」。留空则由管线自动生成；填了则用你给的 |

## 示例（jsonl）

```jsonl
{"user_input": "系统支持上传哪些格式的文档？", "reference": "支持 PDF、Word、Excel、PPT、Markdown、TXT 等格式。"}
{"user_input": "混合检索是怎么实现的？", "reference": "稠密向量 + BM25 稀疏双路召回，经 Rerank 重排序后生成答案。"}
```

## 准备建议

- **数量**：20~50 条即可，覆盖知识库里真实存在的内容（否则检索不到、分数无意义）。
- **质量**：`reference` 写「理想答案要点」，不必逐字一致；Ragas 评的是语义对齐，不是字符串匹配。
- **覆盖**：尽量覆盖不同文档、不同问法（精确术语问法 + 口语化问法），更能暴露召回短板。
- **避坑**：问题必须能在现有知识库中找到答案；问库里没有的内容只会拉低分数、没有参考意义。
